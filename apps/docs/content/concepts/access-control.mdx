# Access control

Each collection has one rule per operation: `read`, `create`, `update`, `delete`. A rule returns `true`, `false` or a `where` filter. It may be async.

```ts
import { defineCollection, fields as f } from "@quickben/core";

export const posts = defineCollection({
  slug: "posts",
  fields: {
    title: f.text({ required: true }),
    status: f.select({ options: ["draft", "published"], required: true, default: "draft" }),
    author: f.relation({ to: "users" }),
  },
  access: {
    read: ({ user }) => (user ? true : ({ status: { eq: "published" } } as const)),
    create: ({ user }) => user !== null,
    update: ({ user }) => (user ? { author: { eq: user.id } } : false),
    delete: ({ user }) => user?.roles?.includes("admin") === true,
  },
});
```

Anonymous users read published posts. Signed-in users read all posts and edit only their own. Admins delete.

## Results

| Operation | `true`        | A filter                                                                     |
| --------- | ------------- | ---------------------------------------------------------------------------- |
| `read`    | all documents | AND-ed with the query. `findById` of a filtered-out document is `NOT_FOUND`. |
| `create`  | allowed       | The new document, after hooks, must match.                                   |
| `update`  | allowed       | The stored document and the updated document must match.                     |
| `delete`  | allowed       | The stored document must match.                                              |

`false` throws `UnauthorizedError` when there is no user and `ForbiddenError` when there is one.

- `update` and `delete` need read access. A document the user cannot read is `NOT_FOUND`, like `findById`.
- Relation values must point to documents the user can read. Other ids fail validation, as if they did not exist. `overrideAccess` checks only that they exist. On update, ids the document already stores are not checked again.
- Rules apply to whole documents. There is no field-level access: `admin.hidden` only hides a field in the admin, and a field removed by an `afterRead` hook can still be used in `where` and `sort`. Keep secrets in a collection that the user cannot read.

## Defaults

| Situation                     | Behavior              |
| ----------------------------- | --------------------- |
| No rule for an operation      | Signed-in users only. |
| `overrideAccess: true` in ctx | Rules are skipped.    |

```ts
// Trusted server code only, e.g. a seed script or a webhook handler.
await qb.create("tags", { name: "news" }, { user: null, overrideAccess: true });
```

## Rule arguments

| Argument    | Value                                                   |
| ----------- | ------------------------------------------------------- |
| `user`      | `QuickbenUser` or `null`                                |
| `req`       | The `Request`, when the call has one                    |
| `ctx`       | The whole request context, with plugin keys             |
| `qb`        | Local API; `undefined` when UI code calls `checkAccess` |
| `operation` | `"read"`, `"create"`, `"update"` or `"delete"`          |
| `id`        | Document id for `update`, `delete` and `findById`       |
| `data`      | Input data for `create` and `update`                    |

Filters returned by rules use the same [query model](/docs/concepts/query-model) as `find`. They are typed from the collection's fields.
