# Multi-tenancy

`@quickben/plugin-tenancy` keeps the data of each organization separate. Users belong to organizations through memberships. Each membership has a role, and roles grant capabilities.

```sh
pnpm add @quickben/plugin-tenancy
```

## Setup

```ts filename="quickben.config.ts"
import { defineConfig, devAuth } from "@quickben/core";
import { memoryAdapter } from "@quickben/db-memory";
import { tenancy } from "@quickben/plugin-tenancy";

import { posts, tags, users } from "./collections";

export default defineConfig({
  db: memoryAdapter(),
  collections: [users, tags, posts],
  modules: [{ key: "blog", label: "Blog", collections: ["posts", "tags"] }],
  plugins: [tenancy({ scope: ["posts", "tags"] })],
  auth: devAuth(),
});
```

`posts` and `tags` now have an `organization` field. Every read, update and delete is limited to the active organization. Creates get its id.

```ts filename="types.ts"
import type { InferDoc, InferRegistry } from "@quickben/core";

import type config from "./quickben.config";

type Post = InferDoc<InferRegistry<typeof config>["posts"]>;

export const organizationOf = (post: Post): string => post.organization;
```

The field is typed. It is optional in create input because the plugin fills it.

List `tenancy()` after the plugins that add scoped collections.

## What it adds

| Addition             | Fields or behavior                                                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `organizations`      | `name`, `slug` (unique), `status` (see [Statuses](#statuses)), `modules`, `metadata`                                                 |
| `memberships`        | `organization`, `user`, `email`, `role`, `status` (`invited`, `active`, `disabled`), `modules`, `invitedBy`, `invitedAt`, `joinedAt` |
| `organization` field | On each collection in `scope`: relation, required, indexed                                                                           |
| `ctx.organizationId` | Optional key of the request context                                                                                                  |

An invitation is a membership with status `invited`. The creator of an organization becomes its owner.

## Options

| Option                  | Default                                      | Purpose                                                                 |
| ----------------------- | -------------------------------------------- | ----------------------------------------------------------------------- |
| `scope`                 | required                                     | Slugs of tenant-scoped collections.                                     |
| `roles`                 | owner, admin, member, viewer                 | Capabilities per role, highest rank first.                              |
| `ownerRole`             | `owner`                                      | Every organization keeps one active member with this role.              |
| `defaultRole`           | `member`                                     | Role of new memberships.                                                |
| `isPlatformAdmin`       | `user.roles` includes a `platformRoles` role | Platform staff.                                                         |
| `platformRoles`         | `["platform-admin"]`                         | Roles that make a user platform staff.                                  |
| `statuses`              | `active` (full), `suspended` (limited)       | Organization statuses. See [Statuses](#statuses).                       |
| `defaultStatus`         | the first status                             | Status of new organizations.                                            |
| `onOrganizationDelete`  | `"restrict"`                                 | `"restrict"` or `"cascade"`. See [Deleting](#deleting-an-organization). |
| `canCreateOrganization` | any signed-in user                           | Who may create organizations.                                           |
| `defaultModules`        | `"all"`                                      | Modules of a new organization.                                          |
| `header`                | `x-quickben-organization`                    | Header with the active organization id.                                 |
| `cookie`                | `quickben-organization`                      | Cookie with the active organization id.                                 |

## Roles

| Role     | Capabilities                                                                    |
| -------- | ------------------------------------------------------------------------------- |
| `owner`  | `read`, `write`, `members:manage`, `organization:manage`, `organization:delete` |
| `admin`  | `read`, `write`, `members:manage`, `organization:manage`                        |
| `member` | `read`, `write`                                                                 |
| `viewer` | `read`                                                                          |

Roles are data. Replace them with your own:

```ts
import { defaultRoles, tenancy } from "@quickben/plugin-tenancy";

export const plugin = tenancy({
  scope: ["posts"],
  roles: { boss: [...defaultRoles.owner, "billing"], staff: ["read", "write"] },
  ownerRole: "boss",
  defaultRole: "staff",
});
```

## Active organization

| Order | Source                            |
| ----- | --------------------------------- |
| 1     | `ctx.organizationId`              |
| 2     | The header                        |
| 3     | The cookie                        |
| 4     | The user's only active membership |

The user must be an active member and the organization's status must give full access. Otherwise the call throws `OrganizationError` (403) with a `reason`:

| `reason`     | When                                                             |
| ------------ | ---------------------------------------------------------------- |
| `none`       | The user has no active membership.                               |
| `ambiguous`  | Several memberships and none selected.                           |
| `not-member` | The selected organization has no active membership for the user. |
| `unknown`    | The selected organization does not exist.                        |
| `suspended`  | The organization's status is `suspended`.                        |
| `inactive`   | Another status without full access.                              |

Without a user the error is `UnauthorizedError`.

```ts
import { OrganizationError, resolveTenant } from "@quickben/plugin-tenancy";

try {
  const tenant = await resolveTenant(qb, { user, req });
  console.log(tenant.organizationId, tenant.role, tenant.capabilities);
} catch (error) {
  if (error instanceof OrganizationError && error.reason === "ambiguous") {
    // Show an organization picker.
  }
}
```

**Platform staff** (`isPlatformAdmin`) skip the membership check, and the status check unless the status limits staff. With nothing selected they see every organization, except the scoped documents of organizations whose status limits staff. With an organization selected they act inside it with every capability.

## Scoped collections

| Operation | Rule                                                                                          |
| --------- | --------------------------------------------------------------------------------------------- |
| read      | Your rule AND `{ organization: { eq: active } }`. Needs `read`.                               |
| create    | `organization` is set from the active organization. Another value is rejected. Needs `write`. |
| update    | Your rule AND the organization filter. A document cannot move. Needs `write`.                 |
| delete    | Your rule AND the organization filter. Needs `write`.                                         |

Anonymous users are denied. If the collection belongs to a module, the user also needs the module.

- Relation fields can only point to documents the user can read, so a document cannot link to another organization's documents.
- Documents of other organizations are `NOT_FOUND`, also for `update` and `delete`.
- Platform staff move a document by updating `organization` with no organization selected.
- In an organization whose status is not `full`, scoped collections throw `OrganizationError` for members. See [Statuses](#statuses).

## Statuses

Statuses are data. Each one has an access level for members, and optionally for platform staff (default `full`).

| Level     | Scoped data    | The organization and its memberships           |
| --------- | -------------- | ---------------------------------------------- |
| `full`    | read and write | read and write, by role                        |
| `limited` | no access      | read only                                      |
| `none`    | no access      | hidden; members still see their own membership |

```ts
import { tenancy } from "@quickben/plugin-tenancy";

export const plugin = tenancy({
  scope: ["posts"],
  statuses: {
    onboarding: { access: { members: "limited", staff: "full" }, label: { en: "Onboarding" } },
    active: { access: "full" },
    suspended: { access: "limited" },
    closed: { access: "none" },
  },
});
```

New organizations get `onboarding` (the first status). Platform staff set it up, then switch it to `active`. Only platform staff change `status`. A stored status that is no longer configured counts as `none` for members.

The admin label is `label`, else the `tenancy.status.<name>` message, else the name.

## Modules

Organizations enable modules from `config.modules` in `organization.modules`. Only platform staff change that list. An entry is a module key, or `{ key, expiresAt, source }`:

```ts nocheck
await qb.update(
  "organizations",
  orgId,
  { modules: ["blog", { key: "reports", expiresAt: "2027-01-01T00:00:00Z", source: "pro" }] },
  { user: null, overrideAccess: true },
);
```

From `expiresAt` on, the module counts as disabled in scoped access, `canUseModule` and `moduleAccess`. `source` is free text, for example a plan key. Entries without expiry or source are stored as plain keys, so existing lists stay valid. `activeModules(organization.modules)` returns the keys in use now. A membership grants a subset in `membership.modules`; an empty list grants every module of the organization.

```ts
import { defineCollection, fields as f } from "@quickben/core";
import { canUseModule, moduleAccess } from "@quickben/plugin-tenancy";

export const reports = defineCollection({
  slug: "reports",
  fields: { name: f.text({ required: true }) },
  access: moduleAccess("reports", { read: () => true }),
});

export const showReports = await canUseModule(qb, { user }, "reports");
```

Use `moduleAccess` for collections outside `scope`.

## Guard rails

| Rule                                                                            | Error                                           |
| ------------------------------------------------------------------------------- | ----------------------------------------------- |
| Membership changes need `members:manage` in the organization.                   | `ForbiddenError`                                |
| The last active owner cannot be demoted, disabled or removed.                   | `TenancyRuleError` `last-owner`                 |
| Owners and admins cannot change their own role or status, or remove themselves. | `TenancyRuleError` `own-role`, `own-membership` |
| Nobody grants or manages a role ranked above their own.                         | `TenancyRuleError` `higher-role`                |
| A membership keeps its organization, and its user once set.                     | `ValidationError`                               |
| Granted modules must be enabled for the organization.                           | `ValidationError`                               |
| One membership per user or email per organization.                              | `ConflictError`                                 |

Platform staff and `overrideAccess` skip the role rules. The last-owner rule always applies.

`TenancyRuleError` extends `ForbiddenError`; `rule` says which rule failed.

Invitations by email need a verified address. Set `emailVerified` on the user in your auth adapter: with `emailVerified: false`, `acceptInvitation` throws `ForbiddenError`, and `listMyInvitations` and membership reads ignore the email. Invitations by user id do not check it. When the field is missing, the email is trusted, so return only verified addresses in `email`.

## Deleting an organization

| `onOrganizationDelete` | Effect                                                                                                                                  |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `"restrict"` (default) | The delete throws `TenancyRuleError` `not-empty` while any scoped document of the organization exists.                                  |
| `"cascade"`            | Scoped documents are deleted through the local API, in the transaction of the delete. Their hooks run. A failure rolls everything back. |

Memberships are always deleted with the organization.

## Helpers

Each helper takes `(qb, ctx, …)` and calls the local API, so access rules apply.

| Helper                | Purpose                                                       |
| --------------------- | ------------------------------------------------------------- |
| `resolveTenant`       | Active organization, membership, role, capabilities, modules. |
| `hasCapability`       | Check one capability in the active organization.              |
| `canUseModule`        | Check one module in the active organization.                  |
| `listMyOrganizations` | The user's active memberships with organizations, by name.    |
| `listMyInvitations`   | Pending invitations for the user's id or email.               |
| `inviteMember`        | Create an `invited` membership.                               |
| `acceptInvitation`    | Make an invitation `active` for the current user.             |
| `updateMembership`    | Change role, status or modules.                               |
| `removeMember`        | Delete a membership.                                          |
| `switchOrganization`  | Check access and return the cookie to set.                    |
| `isPlatformStaff`     | `isPlatformAdmin` of the installed plugin, for `(qb, user)`.  |

```ts
import { inviteMember, switchOrganization } from "@quickben/plugin-tenancy";

const ctx = { user, req };
await inviteMember(qb, ctx, { email: "ana@example.com", role: "viewer" });

const { cookie } = await switchOrganization(qb, ctx, "org-id");
// In a server action: (await cookies()).set(cookie.name, cookie.value, cookie.options)
```

The cookie is `HttpOnly`, `SameSite=Lax` and `Path=/`. It is `Secure` when the request is https (`x-forwarded-proto`, else the request URL), so it also works on `http://localhost`. `organizationCookie(qb, id, req)` without `req` always sets `Secure`. `isSecureRequest(req)` is the check.

## Admin UI

```tsx nocheck filename="app/admin/[[...segments]]/page.tsx"
import { createAdminPage } from "@quickben/admin";
import { tenancyAdmin } from "@quickben/plugin-tenancy/admin";

import config from "../../../quickben.config";

export default createAdminPage(config, { extensions: [tenancyAdmin(config)] });
```

| Part                  | What it does                                                                            |
| --------------------- | --------------------------------------------------------------------------------------- |
| Sidebar switcher      | Pick the active organization. Platform staff can pick any, or all.                      |
| `/admin/members`      | List members, invite, change role, status and modules, remove.                          |
| `/admin/organization` | Rename the organization. Platform staff set status and modules. Create an organization. |

`tenancyAdmin(config, { basePath, group, sections })`: pass the same `basePath` as `createAdminPage` when it is not `/admin`. `group` is the sidebar group (default `Organization`).

### Added fields

Fields you add to `organizations` or `memberships` with `addFields` show up in the admin, with the generic admin inputs and [field access](/docs/concepts/access-control):

| Collection      | Where                                            |
| --------------- | ------------------------------------------------ |
| `organizations` | Organization settings form                       |
| `memberships`   | A **Details** dialog per row on the Members page |

```ts
import { definePlugin, fields as f } from "@quickben/core";

import type { AccessArgs } from "@quickben/core";

const isStaff = ({ user }: AccessArgs) => user?.roles?.includes("platform-admin") === true;

export const hostFields = definePlugin({
  name: "host-fields",
  addFields: {
    organizations: { plan: f.select({ options: ["free", "pro"], access: { update: isStaff } }) },
    memberships: { jobTitle: f.text() },
  },
});
```

List it after `tenancy()`. Fields with `admin: { hidden: true }` are left out.

### Settings sections

Each section is a tab at `<basePath>/organization/<key>`, in full and embedded mode. The component is a server component and can use its own server actions.

```tsx nocheck
import type { OrganizationSectionProps } from "@quickben/plugin-tenancy/admin";

function Billing({ organization, tenant }: OrganizationSectionProps) {
  return (
    <p>
      {organization.name}: {tenant.role}
    </p>
  );
}

tenancyAdmin(config, {
  sections: [{ key: "billing", label: "Billing", component: Billing, visible: (t) => t.platform }],
});
```

| Prop                                                         | Value                                       |
| ------------------------------------------------------------ | ------------------------------------------- |
| `organization`, `tenant`                                     | The active organization and the user in it. |
| `segments`                                                   | Path segments after the key.                |
| `basePath`, `searchParams`, `i18n`, `serverFunction`, `user` | As on admin pages.                          |

Other plugins export a section object; the host passes it in `sections`.

All changes go through the helpers above, so the guard rails apply. Actions redirect with a code (`?toast=member-updated`, `?error=last-owner`). The pages map codes to fixed messages and ignore unknown codes, so the URL never puts text on the page. The playground runs this with `QUICKBEN_TENANCY=1`.

## Admin languages

The admin pages ship English and Spanish messages in the `tenancy` namespace (`tenancyMessages` from `@quickben/plugin-tenancy/admin`). They follow the admin locale. Override a message with `admin.messages`, for example `{ es: { "tenancy.<key>": "…" } }`. See [Languages](/docs/nextjs/admin#languages).

For a host layout with `chrome: "none"`, render the switcher alone:

```tsx
import { createOrganizationSwitcher } from "@quickben/plugin-tenancy/admin";

const OrganizationSwitcher = createOrganizationSwitcher(config, { basePath: "/data" });
// In your layout, inside <Suspense>: <OrganizationSwitcher />
```
